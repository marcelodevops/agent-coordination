## Summary of implementation and correction-round fixes

1. **Read-Only Local Server (`dashboard/server.py`, `dashboard/__main__.py`)**:
   - Standard-library `ThreadingHTTPServer` binding to `127.0.0.1:8787` by default with optional `--host`, `--port`, and `--root` flags.
   - Permits `GET` and `HEAD` only; rejects `POST`, `PUT`, `DELETE`, and `PATCH` with `405 Method Not Allowed`.
   - Exposes `GET /api/state` and `GET /api/file?path=<repo-relative-path>`.
2. **Finding 1 — Active Team & Removed Agents (`active_team` and `removed_agents`)**:
   - Derives active actor cards (`agents`) from `plan.json` `active_team` when present (`["Eiren", "Mr.Q", "agy"]`), or falls back to `[coordinator] + [task owners]` minus `removed_agents`.
   - `Copilot` is excluded from active actor cards and never appears as `completed 0/0`.
   - Historical runs from removed agents are preserved in `runs` and task run history with `owner_removed: true`.
3. **Finding 2 — Process Observation State (`observation_state`)**:
   - Preserves original `execution_state` (`running` / `finished` / `failed` / `launch_failed`) as the worker report without modifying historical run files on disk.
   - Checks local PID presence via `os.kill(pid, 0)` for runs marked `running`:
     - If the PID is gone (`ESRCH`), sets `observation_state: "interrupted"`, `pid_alive: false`, and `elapsed_seconds: null` so disappeared processes never accrue live runtime forever.
     - If the PID is missing/invalid, sets `observation_state: "unknown"`, `pid_alive: false`, and `elapsed_seconds: null`.
     - If the PID exists locally, sets `observation_state: "pid_present_unverified"`, `pid_alive: true`, and labels clearly that PID presence does not prove active task progress or coordinator acceptance.
4. **Finding 3 — Defensive Validation of Malformed Task Fields**:
   - Validates `dependencies`, `evidence`, `assignment`, `reviewed_at`, `review_history`, `active_team`, and `removed_agents` types at the data boundary.
   - Valid JSON with a malformed `dependencies` or `evidence` field (e.g., an integer) records a structured validation diagnostic in `errors` and returns `status: "degraded"` without throwing an unhandled server exception.
5. **Finding 4 — Isolated Temporary Fixture Tests & Dynamic UI Labels**:
   - Removed the live-repository assertion test from `dashboard/tests/test_dashboard.py`; all 7 unit tests run exclusively against isolated `tempfile.TemporaryDirectory()` fixture roots.
   - Removed hardcoded `Copilot` references from `dashboard/static/index.html`; owner filter options and header team labels are populated dynamically from `active_team` / `data.agents`.

## Remaining limitations

- State updates use 3-second HTTP polling rather than push sockets.
- Local PID check (`os.kill(pid, 0)`) detects disappeared worker processes (`observation_state: "interrupted"`), but cannot verify that an existing or recycled PID is actively making task progress (`observation_state: "pid_present_unverified"`).
- Automated tests verify HTTP endpoints, headers, JSON contracts, and path/symlink containment via `urllib.request` against temporary fixture roots rather than driving a real headless browser engine.
- Worker process completion is not coordinator acceptance; acceptance remains pending Eiren's review.
