## Goal

Fix two defects in the generated Helm chart so it lints and templates with **native helm**.

## Changed files (within ownership only)

- `bootstrapper/templates.py` — HELM SECTION ONLY, 3 lines:
  - `_helpers.tpl` `"$name.fullname"` define: the two value lines were `{{ ... }}` and did not left-chomp, so the `if/else` newlines leaked into the rendered name. Now `{{- .Values.fullnameOverride | ... }}` and `{{- printf "%s" .Chart.Name | ... }}`.
  - `templates/deployment.yaml`: image tag now `{{ .Values.image.tag | default .Chart.AppVersion }}` (empty default → `1.0.0`; explicit override still wins).

No other stack template, the renderer, CLI, composer, agents, presets or `pyproject.toml` were touched. A1's accepted changes (`cli.py`, `composer.py`, `test_output_path_contract.py`) are preserved, not reverted. `PyYAML` used in tests only; dependencies unchanged.

## Root cause of the invalid YAML

`{{- if .Values.fullnameOverride }}` closes with `}}` (no right-chomp) and the value lines started with `{{ ` (no left-chomp), so `include "$name.fullname"` returned a leading `\n`. `name: {{ include ... }}` rendered `name:\nmyapp`, which helm reported as `line 6: could not find expected ':'`.
