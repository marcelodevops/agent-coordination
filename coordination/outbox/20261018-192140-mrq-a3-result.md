## What changed (ownership: `bootstrapper/cli.py` + NEW `tests/test_creation_safety.py`)

1. **Identity contract — `_validate_name`** (top of `create`, `init`, `init_from_tree`).
   A project name is used directly as the local directory and as a package/repo
   identity, so it must be a single safe path segment. Documented conservative
   contract: `^[A-Za-z0-9\u00C0-\u024F][A-Za-z0-9._\u00C0-\u024F-]{0,99}$` plus an
   explicit `.`/`..` refusal. Rejects absolute paths, traversal, nested paths,
   spaces, quotes, control chars and option-like `-lead`; accepts `demo`,
   `new-project`, `my_app`, `core.v2`, `café`. Runs before compose/write, so an
   invalid name never creates a target and never runs hooks.
2. **Option contract — `_reject_contradictory_options`** (before compose).
   Rejects `--clone` without `--create` (no remote to connect to) and `--clone`
   with `--no-git` (clone needs git to wire origin + commit). `--remote` without
   `--create` keeps its existing informational "not uploading" behavior. No
   remote/network action is invoked. The now-dead `--clone --no-git` note branch
   in `create` was removed.
3. **Atomic staging for new targets — rewritten `_write_local`.** For a previously
   absent (or empty) target the whole scaffold is written into a temporary sibling
   `.projboot-staging-<name>.*` created via `tempfile.mkdtemp(dir=parent)`, then
   `staging.replace(target)` renames it into place only after every file succeeds.
   On any `OSError` the handler removes **only its own staging**
   (`shutil.rmtree(..., onerror=_force_remove)`) and exits 1, leaving the requested
   target absent — no partial project.
4. **Existing-target preflight.** A non-empty existing target still requires
   `--force` (unrelated files are preserved; no transactional overwrite is
   promised). Before the first in-place write, `_reject_existing_fs_conflicts`
   scans on-disk types: a planned file colliding with an existing directory, or a
   planned nested path whose ancestor is an existing file, aborts cleanly with no
   partial writes. Writing into an existing non-directory target is also refused.
5. **A1 safeguards preserved.** `find_output_conflicts`, `_safe_join` containment,
   and `_reject_resolved_collisions` (resolved `..`/symlink aliases) still run
   before any write.
6. **NEW `tests/test_creation_safety.py`** (30 tests, stdlib + CliRunner only, no
   network): valid/invalid identity parametrization (with a no-write assertion that
   avoids the `work / "/abs"` aliasing trap), `--clone` contradiction rejection with
   a `run_post_hooks` tripwire, `--remote`-without-`--create` still succeeding,
   successful new creation publishing all files with no staging leak, an injected
   `write_text` `OSError` proving no partial target/staging, a staging escape guard,
   an existing-file-blocks-planned-directory no-partial-write case, and `--force`
   preserving unrelated files.

## Limits (honest)

- No atomic guarantee for `--force` overwrite of an existing directory (by design:
  unrelated files must survive, so no whole-dir swap). A disk failure mid-merge can
  still leave that merge partial; the up-front type-conflict preflight only removes
  the *detectable* file/dir conflicts.
- Staging requires the target's parent to be on the same filesystem (it is, it's a
  sibling) and does not cross-mount `rename`. If `staging.replace()` fails (e.g. a
  racy non-empty target appearing mid-run) staging is removed and the target is left
  as found; the pre-existing dir's contents are never deleted.
- Name contract is deliberately conservative; if a supported ecosystem later needs a
  broader identity (e.g. scoped `@org/pkg`), that is a documented contract change,
  not silently widened here.
- No destination flag added; CLI not otherwise refactored; no remote/network
  exercised.
