## Finding 1 (P2) — `python -m appstarter` was documented but unsupported

Reproduced against a real built **wheel** installed into a disposable venv, run
from outside the source checkout:

```
$ venv/bin/appstarter        → Hello from my-app!
$ venv/bin/python -m appstarter
No module named appstarter.__main__; 'appstarter' is a package and cannot be
directly executed                                          (rc=1)
```

Fix: added `src/appstarter/__main__.py` to the template (a three-line module
entrypoint delegating to the existing `main()`; a comment records that without it
the README documents a command the artifact does not support). `[tool.setuptools]
packages = ["appstarter"]` already ships every module in the package, so the file
lands in the wheel with no packaging change.

Native installed-wheel regression added —
`test_documented_module_entrypoint_runs_from_installed_wheel`:

- asserts the generated **README actually contains** `python -m appstarter`, so the
  test cannot silently stop covering a documented command;
- runs `python -m appstarter` from a sibling `elsewhere-module/` directory (no
  source tree on the path, installed artifact only) and requires
  `Hello from my-app!`;
- asserts `appstarter/__main__.py` is present in the **built wheel's** namelist,
  not just in the source tree;
- re-runs the console script in the same outside-the-checkout directory, because
  the existing entrypoint must keep working.

`test_documented_entrypoint_runs_outside_the_checkout` (r1) is preserved and now
carries the same "must be a documented command" guard for `appstarter`.

Live confirmation through the real CLI, following the README quickstart verbatim
(`python -m venv` → `pip install -e .` → both run commands → bare `pytest`):

```

Scaffolded 21 file(s) into my-app/          (20 → 21: __main__.py)
```

That last line is a new assertion too (`test_generated_tests_pass_against_the_

`pytest` is documented on its own, so the documented form — not a smuggled-in
path variant — has to be the one that works.

## Finding 2 (P2) — `.env.sample` and `.env.template` were ignored

The template had `.env.*` with a single exemption `!.env.example`, so the other
two shareable templates were hidden from git. Rejected rules now explicitly
exempt each, instead of loosening the secret-matching pattern:

```
# protect real secrets, keep every shareable template tracked
.env
.env.*
!.env.example
!.env.sample
!.env.template
```

Native `git check-ignore -v` on a freshly generated project, showing which rule
decides each path (secrets matched by a positive rule, templates matched by a
negation, so the outcome is derived from the file and not asserted by me):

```
.env          -> .gitignore:5:.env          IGNORED
.env.local    -> .gitignore:6:.env.*        IGNORED
.env.example  -> .gitignore:7:!.env.example shareable
.env.sample   -> .gitignore:8:!.env.sample  shareable
.env.template -> .gitignore:9:!.env.template shareable
$ git status --porcelain .env.example .env.sample .env.template
?? .env.example / ?? .env.sample / ?? .env.template   (all trackable)
```

`test_ignore_rules_protect_real_env_but_share_the_example` is now parametrized
over those five paths (`real secret → must be ignored`, `template → must not be
ignored **and** must appear in `git status --porcelain`), so real `.env` and
`.env.local` protection is regression-covered alongside the exemptions.

### Why my first probe of this finding was wrong, and how the test prevents it

My hand-run reproduction initially reported `.env.sample` as shareable, which
contradicts the finding. Cause: in this session's shell `git` is a **shell
function** (from `/Users/mac/.qoder/shell-snapshots/…`) that appends its own
ignore block to any `.gitignore` during `git init`, so `check-ignore` was grading
the wrapper's rules, not the product's. Every ignore claim above was re-run
against the resolved binary (`/usr/bin/git`), where the generated file keeps
exactly its own rules and nothing appended. The test resolves the binary explicitly (`GIT =
shutil.which("git")`) and documents this trap in its docstring, so the coverage
cannot be satisfied by an external rewrite. `shutil.which('git')` → `/usr/bin/git`
here, and no wrapper binary sits earlier on `PATH`.
