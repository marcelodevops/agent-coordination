## What changed

Only the TypeScript template section of `bootstrapper/templates.py` and one new test
file. Public template names, description serialization (A2), the Helm fixes (B1), and
all other files are untouched.

1. **`bootstrapper/templates.py` — TypeScript `tsconfig.json`**: added
   `"module": "nodenext"` and `"moduleResolution": "nodenext"` to `compilerOptions`
   (placed right after `"target": "ES2022"`). This is the coherent minimal fix:
   `nodenext` resolution lets `tsc` locate `@types/node`'s transitive `undici-types`,
   and it emits consistent CommonJS so `node dist/index.js` runs without the
   `MODULE_TYPELESS_PACKAGE_JSON` warning. No `skipLibCheck` — that would only mask
   the failure rather than fix it.
2. **`bootstrapper/templates.py` — TypeScript files dict**: added
   `".gitignore": "node_modules/\ndist/\n"` so the generated starter ignores its own
   build/dependency output.
3. **`tests/test_generated_typescript.py`** (NEW): a native integration test that
   materializes the rendered TypeScript template into a fresh temp dir and runs real
   `npm install`, `npm run build`, `npm start`. Skips with an explicit reason when
   `npm` is absent. No source-text mirror assertions.

No CLI, composer, agents, pyproject, README, other templates, or existing tests were
modified.

  package's exports).

  the `dist/index.js` module type was ambiguous.

  (the install/build/run test and the metadata test caught it).
